# Rationale (synthesized)

## Problem

The task is a native Typst editor whose preview follows typing, on a Rust world that compiles one thing at a time and takes 22 to 94 ms per keystroke, or seconds when a package downloads inside compile. Four constraints set the shape. Keystrokes must never be lost or reordered, yet compiles must coalesce. Every result arrives against text that has already moved on. Several files can hold unsaved edits that must reach the compiler. comemo's cache is process-global, so two windows share it. On top of that the app runs in the App Sandbox, the core must build for iOS 27 unchanged, and the spike ABI (JSON results, main-file-only overlay, silent no-op on a bad edit, eviction inside every compile) is a starting point, not a contract.

## Usage (caller's view)

DESIGN.md section 1 holds the usage, and it is the spec. The app opens a window with `WindowGroup(for: ProjectID.self)` and gets a `Project` with `try await Project.open(id, recents:)`. It binds `project.selectedFile`, hands `buffer.storage` to the text view, reads `project.diagnostics`, `project.status`, and `project.preview.pages`, and calls `reveal`, `saveAll`, and `exportPDF`. That is the whole engine surface. The app never sends an edit. Edits leave through the `NSTextStorage` delegate that `TypoKit` installs.

## Shape

- **One funnel, one sequence number.** Every character mutation (typing, paste, undo, spell-correction, find and replace) reaches `Buffer`'s storage delegate, which filters on `.editedCharacters`. `Project.record` then stamps it with a project-wide `Seq`. A result says "covers every edit at or below seq N in every file". That is the per-file revision the task asks for, with no per-file map to keep in sync.
- **Text truth.** `NSTextStorage` per open file is the only writer of text. The Rust overlay is a mirror fed only by the funnel and is seeded with exactly the text the storage holds, never read from disk. Disk is a copy that save writes. Rust never writes files. `tb_world_edit` checks the post-edit UTF-16 length and reports divergence, and the engine answers by resending the full text, so the mirror heals instead of drifting silently (`set_text` is idempotent).
- **Ordering without per-keystroke Tasks.** `Engine.send` is synchronous and nonisolated. It appends to a `Mutex`-guarded FIFO, so the order is the main actor's call order. A single drain loop on the engine's own `DispatchSerialQueue` executor applies everything queued, then compiles once. Coalescing falls out of draining and needs no timer or debounce. Blocking work (compile, package download) stays off the cooperative pool.
- **Staleness: map, not drop.** At 94 ms per compile almost every result is at least one keystroke old, so dropping stale results would hide marks for the whole time the user types. `Project.diagnostics` is derived on every read: the latest result's diagnostics mapped through `EditLog` entries newer than its seq. A diagnostic whose range an edit touched disappears until the next result. Marks, the list, and the jump all read the same derived value, so they cannot disagree, and a range never lands on text it was not computed for (single source of truth, derived instead of synced).
- **ABI: two kinds of handle by thread rule.** `TbWorld` is mutable and used by one thread. `TbSnapshot` is immutable and Sync, so pages render on the global executor while the next compile runs. Typed structs and borrowed `TbStr` replace JSON. Pages come back as `{hash, size}`, and diagnostics come back already in UTF-16, converted while the exact compiled `Source` is still at hand. Sixteen functions.
- **Eviction has one owner because only one call site exists.** `comemo::evict` runs only inside `tb_world_compile`, with an age scaled by the live world count. There is no eviction export, so a second owner cannot be written.
- **Preview keyed by content.** `ImageKey = (page hash, pixelsPerPoint)`. Pages that an edit did not change keep their key, so they hit the cache even when they moved to another index. `PageView.task(id: key)` is the visibility tracker and the re-render trigger at once: LazyVStack creates views only near the viewport, and the task restarts only when the key changes. Images live only in a byte-bounded LRU (256 MB on macOS, 128 MB on iOS) and never in view state. Rust buffers wrap into `CGImage` without a copy.
- **Sandbox in one place.** `RecentProjects` owns every bookmark and is the Open Recent list. `ScopedAccess` holds the grant for the `Project`'s lifetime, and Rust reads disk under that process-wide grant. The `.withSecurityScope` platform difference is one branch in `register`.
- **Interface depth.** The app-facing surface is one class (`Project`) with about a dozen members, plus value types. It hides the thread, the FIFO, revisions, mapping, the C handles, eviction, font indexing, and caching. `internal import TypstBridge` makes the C types unreachable from the app at build time.
- **Deliberately absent.** Debounce timers, a separate diagnostics store, per-file revision maps, NSDocument, a UI package, closing buffers, a cancel API (typst has none), and a tb_evict.

## Synthesis decision

Base: the opus candidate. The sonnet candidate converged on the same shape independently (NSTextStorage as the only text owner, delegate funnel, mutex inbox drained by one loop, immutable snapshot that renders off-thread, content-hash image keys, `WindowGroup(for: ProjectID)`, map stale diagnostics through an edit log). The cross-judge (sonnet) scored opus 28, sonnet 24, haiku 18 and recommended the same base. Opus won on the single project-wide `Seq` (one number instead of a per-file revision map), the length check that detects a diverged mirror, diagnostics derived on read instead of stored, `internal import` hiding C types at build time, and the smallest module map.

Grafted:
- From sonnet: the lone-`.typ` sandbox flow (second folder panel, root is always a granted folder); packages in Application Support instead of Caches, so offline compiles survive cache purges; boundary validation in `RelPath.init?`.
- From sonnet, reworked: the stack-depth concern. Sonnet ran the engine on a dedicated 64 MB thread. Here the Rust side wraps compile in `stacker::grow(32 MB)` instead, so the Swift side keeps a plain `DispatchSerialQueue` executor. typst-eval already depends on stacker; layout recursion is unguarded.
- From haiku: a hard cap of two concurrent page renders with a cancellation check after acquiring a slot, so flinging through 150 pages does not queue 150 renders.

Rejected:
- Haiku's full-text snapshot per keystroke: O(file) copy and diff per key, and its `pending` map can apply a late older revision after a newer one (cross-judge defect C-D1).
- Haiku's single compile queue for all windows: one window's package download stalls every window, and per-compile eviction still ages out the other windows.
- Haiku's claim that `FontStore` is not `Send`: wrong against the source (`FontSource: Send + Sync + Any`).
- Haiku's background font load with a later reload: it would show fallback fonts and then reflow on first launch. The 2 s wait happens once per install; warm launches only stat the font files.
- Sonnet's per-file revision map, time-driven `CacheJanitor`, `PageSlot` objects and six-target module split: more state to keep in sync for the same behavior.

## Tradeoffs accepted

- We accept that buffers stay open until the window closes in exchange for never needing a close-then-drop-overlay protocol. The memory cost is about the size of the text.
- We accept that a diagnostic disappears for one compile after an edit touches its range, in exchange for never showing a mark on the wrong text.
- We accept a first-launch wait of about 2 s for the font index before the first compile, in exchange for a `FontBook` that never changes under a live world. Later launches only stat each font file.
- We accept that `diagnostics` is recomputed on every read, costing O(diagnostics × unacknowledged edits), in exchange for having no stored copy to keep in sync. The log is trimmed on every result, so it is usually only a few entries long.
- We accept that the preview keeps showing the last successful document while the code has errors. This is standard Typst preview behavior.
- We accept eviction tuned by a heuristic (10 × live worlds) in exchange for zero eviction API.

## Alternatives considered

- **A Swift `actor` with one `await engine.edit(...)` per keystroke.** It looks idiomatic, but separate unstructured Tasks have no FIFO guarantee, so edits can reorder. It also pins a cooperative thread during a download. Rejected for the sync inbox.
- **Engine owns the text (a Swift `String` or the Rust `Source` as truth, with the view as a projection).** This gives two writers whenever the text view edits locally, which is split ownership. The other direction (the view asks the engine) puts FFI on the keystroke path. Rejected.
- **Drop stale results and wait for a fresh one.** This is simpler, but marks would never appear while the user types steadily on long documents, or during a 2 s download. Rejected for mapping through the log.
- **NSDocument or `DocumentGroup` per file.** It brings autosave and undo for free, but a folder project with many files in one window fights the document model, and the iPad needs a different one (`UIDocument`). Rejected for `Buffer` plus `saveAll`.
- **JSON across the ABI (spike style).** It is smaller in C, but stringly typed, and needs an allocation and a parse per compile. Typed structs cost a few more functions and remove a parse layer.
- **Swift owns comemo eviction (a `tb_evict` called by a runtime singleton).** That is one owner by convention only. A future caller can add a second. Rejected.

## Implementation reconciliation

Deviations found while implementing Unit 1 (bridge and `TypoKit`). The ABI header is unchanged except for one addition.

- **ABI: `tb_world_text`.** One extra function, `TbBytes tb_world_text(const TbWorld *, TbStr path)`, returns the Rust overlay text (ptr NULL when there is no overlay). It exists so tests can read the mirror back; the Swift wrapper is internal (`WorldHandle.text(of:)`, `Engine.overlayText`), reachable only through `@testable import`.
- **`Snapshot.pages` is computed, not stored.** DESIGN stores `let pages: [PageInfo]` while `PageInfo` holds `snapshot: Snapshot`, which is a retain cycle that would leak one `PagedDocument` per compile. `Snapshot` keeps `(hash, size)` metadata and builds `PageInfo` values on demand.
- **`tb_world_edit` split check.** `Lines::utf16_to_byte` rounds a mid-surrogate index up to the next scalar instead of failing, so the bridge round-trips through `byte_to_utf16` to detect a range that splits a scalar (DESIGN says it must return false).
- **`Engine.flush()` compiles once if nothing has compiled yet.** Otherwise `flush()` on a fresh engine with an empty inbox would return nil.
- **`RecentProjects.Record` gains `rootPath`** (to reuse the ID for an already-registered folder without resolving every bookmark) and is a public struct with internal bookmark storage. `ProjectID` gets a public `init()`. `RecentProjects.init(defaults:)` takes a `UserDefaults` for tests.
- **`ScopedAccess`** tolerates `startAccessingSecurityScopedResource() == false` (normal outside the sandbox) and `Project.access` is optional so tests can open a project from a plain folder URL with an internal initializer.
- **`RelPath`** also rejects "." components.
- **`Project.autosaveDelay`** (default 1.5 s, nil disables) is added so tests can keep disk untouched. The `ProcessInfo.disableSuddenTermination()` hold, scene-background and window-close saves are app-layer and left to Unit 2.
- **Date.** `World::today` uses `typst_kit::datetime::Time::system()` (feature `datetime`), not a fixed date.
- **Buffer delegate methods are `public nonisolated`** (required because the protocol is public) and read text from `self.storage` inside `MainActor.assumeIsolated` (the `NSTextStorage` parameter cannot be sent across the isolation boundary under Swift 6).
- **Cross-platform name.** The edit-actions type is `NSTextStorageEditActions` on macOS and `NSTextStorage.EditActions` on iOS, so `Buffer.swift` declares a public `EditActions` typealias (public because the delegate methods that use it are public).
- **Linker settings.** `TypoKit` links Security, CoreFoundation and SystemConfiguration explicitly, because the Rust staticlib carries no link directives.
- **Unit 2 core additions (three, all in `Project`).** `hasUnsavedChanges` (observable; set in `record`, recomputed after `saveAll`) drives `ProcessInfo.disableSuddenTermination()` and the quit check, because `Buffer.isDirty` is not observable. `selectionRequests` is bumped by `reveal` after `requestSelection`, because `pendingSelection` is not observed and a diagnostic click in the already-selected file would otherwise never reach `updateNSView`. `buffer(for:)` lets the diagnostics list turn a range into a line number.
- **Unit 2 app notes.** Quit handling lives in `AppDelegate.applicationShouldTerminate` (`.terminateLater`, replies `false` and alerts if a save fails) and save-on-close in `ProjectWindow.onDisappear`; both go through `OpenProjects`, an app-level registry. Diagnostics for a file that has not been opened show `file` without a line (no buffer to count in). The sidebar filters FileNode to folders and `.typ` in the view, because `FileNode` has no public initializer. Finder Open With is handled by `.onOpenURL` in `WelcomeView` and `ProjectWindow`, and the Info.plist/entitlements are generated by xcodegen from `project.yml`. The line-number gutter counts newlines from the file start per redraw.
- **Bug-fix pass.** `Project.init` now sets `selectedFile = main` (it was nil, so the editor showed no file). `PreviewModel.zoom` is relative to the column-fit page width (zoom 1 = fit), not to 72 dpi points; `PageView` takes `fitWidth` from a `GeometryReader` and the `ImageKey` scale is `displayScale * displayedWidth / page.size.width` (still rounded to 1/8 by `ImageKey`). The line-number ruler also redraws on the text view's frame change, which covers a swapped storage.
- **Syntax highlighting (section 5).**
  - ABI is as designed; `tb_world_edit` and `tb_syntax_edit` share one `checked_edit` helper (bounds, surrogate-split round trip, expected length).
  - Spans are leaf-level: `highlight()` tags a node and its descendants (Strong covers its Text), so each leaf gets the innermost tag of itself or an ancestor. Empty leaves are skipped. A nested tag therefore replaces its parent's (bold is lost on `_x_` inside `*...*`).
  - Prose: besides `SyntaxKind::Text` outside `Raw`, `SmartQuote` leaves count and adjacent ones are merged into one range. Without this "don't" is three leaves and the app's filter (result range must lie inside one prose range) would drop every contraction.
  - Delegate: `willProcessEditing` captures the character edit (pre-range, replacement) before any attribute write and feeds the mirror; highlighting runs in `didProcessEditing` just before the engine forward (superseded: it first ran in `willProcessEditing`, which moved the caret; see the polish batch below). The forwarded capture is used because `didProcessEditing`'s own `editedRange` is attribute-inflated.
  - `Highlighter.recolor` resets the dirty range with `setAttributes(base)` (font and `textColor`/`label`), so no stale attribute survives. Bold is a second font; emph uses `.obliqueness`. The dirty range is exactly what `Source::edit` returns; tests 2 and 3 pass after every step, including a lone `$` mid-paragraph, so no widening was needed.
  - `Buffer.init` highlights the whole text once. `Highlighter.baseFont` is core's monospaced font and the app no longer sets `tv.font` (setting it rewrote every font attribute and lost bold); it sets `typingAttributes = Highlighter.base`.
  - The timing test prints the median (not asserted); Rust is always built `--release`, so Swift Debug/Release differ little.
- **Autocompletion (section 6).**
  - **Answered at its batch position, not after the batch.** The drain loop answers a surviving request when it reaches it in the batch, instead of after applying every edit. A request after later edits would otherwise see text its cursor was not computed against. It is still answered before the batch's compile. The reply carries the engine's `appliedSeq` at that moment; that is `CompletionList.seq`.
  - **A batch of only completion requests does not compile.** The drain loop compiles only if it applied a non-completion message; otherwise every popup would trigger a compile and delay the next request.
  - **`Engine.close()` and `send([EngineMessage])`.** `close()` stops the inbox and resumes queued requests with nil (called from `Project`'s `deinit`; a later `send` of a request replies nil at once). The array `send` appends under one lock so tests can build a deterministic batch. `Engine.stall` is test support.
  - **`Project.endCompletion()`** clears the active list on dismiss, as the task asked. `Project.complete` also clears it when the newest request returns nil or an empty list; a superseded request returns nil without touching it.
  - **Log trim pin.** Besides the latest result and the active list, the trim rule also respects the seq of every in-flight request: a compile result can be handled before the reply's continuation resumes, and would otherwise trim edits that the not-yet-registered list needs.
  - **`live` anchor.** `from` is mapped by mapping the one character before it through the `EditLog`, so an insertion exactly at `from` counts as typed text (not as an edit before it), and an edit that touches that character, such as deleting the `#`, returns nil. `from == 0` never moves. `live` also returns nil when the list is not the active one, the file is not `selectedFile`, or no item matches the typed text (a popup with no rows is never wanted).
  - **`CompletionItem.summary`** (first sentence of `detail`, markup stripped, one line) and **`Snippet.selection(insertedAt:)`** (first placeholder, else the end) are added to the core so the popup and the accept path are testable; `CompletionItem.detail` stays the raw Markdown. `CompletionKind` cases are `syntax, function, type, parameter, constant, path, package, label, font, symbol(glyph)`.
  - **Paths need a closed string.** typst-ide completes paths only inside a terminated string literal (an unterminated `#include "` parses as an error node and yields nothing). `from` is the opening quote and, when the closing quote is already there, `apply` drops the trailing quote, so accepting gives exactly `#include "kapitel.typ"` with no doubled quote. The auto-closing of a typed quote is not implemented.
  - **Bridge.** `TbWorld` stores `root` and `last_doc` (cloned from the snapshot after a successful compile; `PagedDocument` is `EcoVec` plus an `Arc` introspector, so the clone is cheap). Completion runs under `stacker::grow` like compile. When typst-ide returns `None` the reply is an empty list at the cursor, not NULL.
  - **App.** The trigger character is captured in `shouldChangeTextIn` (single character, not marked text, not the accept path) and acted on in `textDidChange`, so paste, undo and programmatic edits never trigger. Hiding on scroll uses the live-scroll start notification, since an automatic scroll to the caret while typing must not close the popup. `EditorView` takes the `Project` for this.
- **Hover info (section 9).**
  - **Request machinery reused unchanged.** `.hover` is a fourth request kind (newest wins globally, answered at its batch position, no compile for a request-only batch, exactly-once resumption). `HoverAnswer.tip == nil` means "no tooltip" and is a normal reply; nil is only superseded, diverged or closed. `Project.hover` returns nil after a superseded or diverged reply, so diagnostics alone do not rescue a stale request.
  - **`HoverInfo.range`** is the mapped tooltip leaf; with diagnostics only it is the first diagnostic's range. Diagnostics are the current mapped ones whose range contains the cursor (an empty range matches at its location).
  - **Tooltips only exist where typst can evaluate.** typst-ide traces the hovered expression by evaluating the module, so an expression after an erroring one has no value or docs tooltip (diagnostics still show). The error test puts the checked expression before the error. Label tooltips also need a compiled document, and a heading label needs numbering (`@intro` on an unnumbered heading is a compile error, so `last_doc` stays empty); only labels with details (headings, figures) give a tooltip.
  - **`HoverText.code` wraps the code in `#{ }`** before handing it to the syntax mirror (which parses markup, where `3` would be plain text) and keeps only the code's own range. `HoverText.markdown` uses `inlineOnlyPreservingWhitespace` (inline Markdown, paragraphs kept as newlines, no block structure); links with a scheme other than http, https or mailto lose their link attribute, and inline code, strong and emphasis are mapped to fonts there because the presentation intents do not survive conversion to a platform attributed string. Both are `@MainActor` (they use `Highlighter`).
  - **App.** The panel (`HoverPopup`) uses a read-only `NSTextView` in a scroll view on the completion popup's material and corner radius; its size comes from `boundingRect`. Glyph hit testing: `characterIndexForInsertion` candidates (index and index minus one) must have a `firstRect` containing the point, and newlines are excluded, so line ends and the margin never hover. The card stays while the mouse is on the hovered range or in the 6 pt rim around the card plus anchor; any other move hides it and restarts the 0.5 s dwell. Hide also on key down (`EditorTextView.keyDown`), live scroll, window resign, file switch and completion popup (all through `dismiss()` or `hideHover()`). Not run in the UI in this pass.
- **Table cell escaping is mode-aware.** `TableCode.escape` parses the cell text with `SyntaxMirror` and asks `mode(at:)` for each `[`, `]` and `\`; only markup (0) and code (1, the balanced brackets of a content block) positions balance or get escaped, so raw, strings, comments and math stay exactly as typed. Previously `` `a[b` `` became `` `a\[b` `` and showed a backslash. A trailing backslash is escaped only in markup; inside an unterminated raw it is left for the compile diagnostic. No bridge change. Math finding, compiled through the engine: `#table(columns: 1, [$[a$])` and `#table(columns: 1, [$a]$])` both compile with no diagnostics and the PDF text is `[𝑎` and `𝑎]`, so unbalanced brackets in math do not end or break the enclosing content block and need no escaping; adding `]` after them (`[$[a$]]`) gives "unclosed delimiter"/"unexpected closing bracket", i.e. the only markup bracket was the extra one.

## Open questions and risks

- Resolved: `FontStore` is shareable (`FontSource: Send + Sync + Any`, `OnceLock` slots), and `FontInfo` is serde, so the index is JSON.
- Two windows downloading the same uncached package at the same moment: does typst-kit's `FsPackages` write atomically (temp dir plus rename)? If not, the runtime needs a per-package lock.
- Can a sandboxed iOS app read system font file URLs returned by CoreText, and does the macOS sandbox need any entitlement beyond `network.client`, `files.user-selected.read-write`, and `files.bookmarks.app-scope`? The spike did not run inside a sandbox.
- Opening a single `.typ` grants only that file in the sandbox. The design shows a second `NSOpenPanel` at the parent folder asking for access. If the user declines, is a file-only project acceptable, with sibling imports failing as diagnostics?
- Resolved: `comemo::evict` takes per-cache `RwLock` write locks and `accelerate::evict` its own lock, so it is safe while another world compiles. The `10 * live worlds` age is a heuristic; a busy window still ages a quiet one at 1/N.
- Autosave is last-writer-wins: an external change to an open file is overwritten. External-change detection is out of scope for the skeleton.
- Does `NSTextContentStorage.textStorage` swapping on one `NSTextView` keep TextKit 2 layout and spell-check state sane across file switches, or should each `Buffer` get its own text view, cached by the editor?
- Does `LazyVStack` on macOS cancel `.task` for views scrolled far away promptly enough to keep render work bounded when the user flings through 150 pages?

## Next implementation step

Rewrite the Rust bridge to the new header (overlays, `TbSnapshot`, eviction inside compile, font index) and test it from a Swift harness that asserts `tb_world_edit` divergence detection and `EditLog.map` on emoji text.
- **Preview flicker fix.** `show` used to evict every image whose hash left the page set before the replacement render landed, so each keystroke showed the white placeholder until the new image arrived. `PreviewModel` now records the newest landed key per page index (`shown`); `retain(hashes:keeping:)` spares those keys, and `image(for:index:)` falls back to the page's last image until its own render lands. When the replacement lands, the superseded key is removed, so memory stays bounded. `PageView` passes `page.id`. Test: `PreviewFlickerTests`.
- **Preview render race fix.** A PageView `.task` for key K cancelled mid-queue and restarted at once used to leave K without an image (the second call returned on `inFlight`, the first bailed on cancellation); seen as a permanently blank preview in a never-front window. `inFlight` is now `[ImageKey: Work]`: one unstructured task per key, shared by all callers. Callers count themselves in (`waiters`) and, if cancelled, out; the work is never cancelled. When it gets a slot with `waiters == 0` it skips rendering (so a fling still renders nothing for scrolled-past pages); otherwise it renders and inserts into the cache. Each caller calls `landed` itself after the await. `Work` carries `page` and `key` because a `UInt128` captured by the Task closure arrived garbled in the debug build. Tests: `PreviewRenderSharingTests` (the restart test failed on the old code).

- **Jump between preview and source (section 7).**
  - **Machinery reused.** `EngineMessage` gained `.click` and `.cursor` next to `.complete`; the drain loop picks the newest request per key (completion per file, click and cursor one global key each), answers it at its batch position before the compile, and resumes the others with nil (`EngineMessage.refuse`, also used by `close()` and by sends after close). `Project.ask` is the one place that pins the log (`inflightRequests`) around a request; `complete`, `click` and the cursor sync all use it, and the mapping through the `EditLog` runs in the same synchronous turn as the unpin.
  - **Granularity is the Text leaf, not the word.** typst-ide reports the position of the first glyph of a span, and a markup `Text` node runs from one markup break to the next ("First paragraph with several words" is one node). `jump_from_cursor` therefore returns the start of the run and a click on it returns the run's start offset (+ glyph offset when the click is inside the run). Test 1 asserts "inside the same leaf" (the design text's own wording); a one-word leaf (`*beta*`) is asserted to be the same word.
  - **Click y.** typst-ide's glyph rectangle spans `[baseline - size, baseline]` and `jump_from_cursor` returns the baseline, so "slightly inside" is `x + 1, y - 1`; `y + 1` misses (it lies below the baseline). The tests use `y - 1`.
  - **Span-survival inference: confirmed for untouched nodes, not for the edited one.** Test 4 inserts a paragraph before the target and clicks in the old document; the caret lands on the same leaf in the new text (offset shifted by exactly the inserted length). Test 4b edits inside the target's own leaf: the old span is gone and the click misses (nil) instead of landing elsewhere. So: spans of nodes outside the reparsed range survive; the reparsed node does not.
  - **Reason for a cursor sync is derived in the core.** `cursorMoved(in:to:programmatic:)` has a defaulted third parameter (not in the spec): the app passes `true` for caret moves it makes itself (pending selection from a reveal or click-to-source, completion accept). The core adds undo/redo (`UndoManager.isUndoing/isRedoing`), compares `Buffer.lastSeq` with the value at the previous report (typing vs navigation), and calls the pure `syncDecision(_:userScrolled:)`. `.resync` (after a newer delivered compile; a duplicate delivery of the same result does not resync) is a fourth `SyncReason` next to the three in the design.
  - **Preview model.** Besides `target` and `followsCursor`, `PreviewModel` carries `targetDecision`, `targetSerial` (an equal target still triggers the view), `targetDate` (a lazily created page view must not replay an old marker) and `userScrolled` (set by the view on interacting/decelerating scroll phases, lifted when a navigation aim lands). A click on an outline entry aims with the navigation decision (scroll if outside, marker).
  - **Flash.** `Buffer.takePendingFlash()` goes with the pending selection; the editor calls `showFindIndicator(for:)` on the word around the caret after applying it.
  - **View.** Target y is computed from page sizes (zoom, 16 pt spacing and padding), not from view frames, because lazy pages have none; scrolling is vertical only (the target is placed a third from the top); x is not scrolled. The marker is an overlay on the page view, fading over about 0.9 s after 0.25 s.
  - **Not done.** No selection-burst coalescing in the editor beyond the engine's newest-wins rule; no refresh of the sync when "Preview Follows Cursor" is switched on (the next move or compile syncs). The cursor feedback is the default arrow.

- **Polish batch (section 8) and the caret jump.**
  - **Caret jump (root cause, fixed).** A failing test with the real `Buffer` behind a TextKit 2 `NSTextView` showed that even a plain character typed mid-paragraph moved the caret to the end of the recolored range (observed 60 for an expected 55, `$` 87 for 35). Cause: attribute writes over a wider range than the edit inside `willProcessEditing` widen the processed edit, and NSTextView places the caret at the end of it. Candidates: (1) recolor in `didProcessEditing`: passes, keeps one pass inside the same `processEditing` and the same run-loop turn, no change to the equal-to-full-highlight tests. (2) a separate async attribute-only pass: rejected, it lets one frame draw stale colour and needs its own coalescing. (3) TextKit 2 rendering attributes: rejected, they cannot carry the bold font for headings and strong. Chosen: (1). `CaretTests.layoutSeesRecoloredAttributes` checks the layout's paragraphs carry the recolored attributes; a visual check of the flash question was not done (no UI driving).
  - **Platform behaviour, not fixed.** `accessibilityRange(for:)` past the end of line 0 returns 0 even on a stock TextKit 2 `NSTextView`.
  - **Selection per file.** Swapping `textContentStorage.textStorage` does not clamp the selection. `Buffer.selection` is recorded by the text view delegate (not while a swap is in progress) and `restoredSelection` clamps it; the editor restores it and scrolls it into view. The raw scroll offset is not remembered (scrolling the caret into view is the cheap, deterministic version); a reveal or click-to-source selection still wins.
  - **Save errors.** `Project.saveError` holds "file: reason" for the last failed save and is cleared only by a later successful save. Quit now uses the same Retry / Discard Changes loop as window close (a failed save no longer cancels the quit; Discard is the user's explicit choice). Cmd-S failures show in the toolbar only.

  - **Freshness without a third file.** "At most once per hour" is the mtime of `preview/index.json` (set when a 200 is written, refreshed on a 304); the etag sits in `preview/index.etag`. - **Tables (section 11).**
  - **Column count** follows typst's resolver (`typst-library` `grid/resolve.rs`): `max(1, columns.len())`, so a missing `columns:`, `columns: ()` and `columns: 0` are all one column, an integer N is N, and an array literal counts its entries. A `columns:` that is not an integer or a plain array literal (no spread) is unsupported.
  - **Extra unsupported cases** beyond the list in section 11: a comment between arguments (a rewrite would drop it), content blocks after the closing parenthesis (`table(columns: 2)[a][b]`), a syntax error inside the call, `table.cell` with `x` or `y` as well as `colspan`/`rowspan`, more than one `table.header` or one that is not first, and a header whose cell count is not exactly one row. Typst pads a short last row; the editor refuses it instead.
  - **Parse shape.** Named args come back with a shape tag (integer, array literal with its entries, single alignment, other), so Swift never re-parses typst syntax. `align:` is editable only when it is absent, a single alignment, or an array of alignments (`left center right start end top horizon bottom auto`, or `a + b`); `auto` entries read as "default". The ABI added `TbTable` and the `tb_table_*` accessors.
  - **Model.** `TableModel.Cell` carries a third field, `initial` (the text as first shown), because "unchanged" must be told apart from "typed the same text" without re-deriving the cell kind. `ColumnSpec` holds the `columns:` entry source and the alignment source. `isModified` compares the render with the render taken at parse time, so toggling the header twice is a no-op even if the source layout differs.
  - **Render details.** An unchanged `columns:` or `align:` value is written back verbatim; otherwise `columns` is an integer unless some column has a size (then an array, new columns `auto`), and `align` is omitted when every column is default, a single value when all columns agree, else an array with `auto` for default. Args the edit newly needs come first (`columns`, then `align`). `TableCode.render` and `edit` take the call's line indentation so a table inside `figure(...)` keeps nesting. Escaping handles brackets by scanning for escapes only; a bracket inside raw text or math in a changed cell is escaped too (a known limit).
  - **Insert.** `TableCode.insert(rows:columns:...)` counts the header row in `rows`. `TableCode.place` adds the newlines before and after when the selection is mid-line.
  - **App.** "Edit Table…" is enabled whenever the caret is in any `table`/`grid` call; an unsupported one shows the reason in an alert instead of the sheet. The Format menu and the context menu have no keyboard shortcut. A right-click moves the caret under the pointer unless it is inside the selection. The sheet's Done is Cmd-Return (Return belongs to the cell fields and moves down).

### Unit: local packages (DESIGN 12.5)
- **Data dir in the loader, not `SystemPackages::from_parts`.** `SystemPackages` owns the downloader and cannot be re-parted, and a world must switch the data dir between compiles. `Loader` therefore holds `data: Option<FsPackages>` and tries `data.obtain(spec)` first, then `SystemPackages` (built with `data: None`: cache, then download). That is the same priority `SystemPackages::obtain` has (data, cache, universe); `FsPackages::new(dir)` is the 0.15.1 API.
- **Swap pattern.** `TbRuntime.data_dir: Arc<RwLock<Option<Arc<PathBuf>>>>`; `TbWorld::refresh_data_dir` compares and rebuilds the loader's `FsPackages` at the start of `tb_world_compile` and `tb_world_complete`, so a compile never sees two dirs. The `FileStore` re-loads every file after `reset()`, so no package file survives from the previous dir.
- **Recompile on change.** `TypstRuntime.packagesChanges()` is an `AsyncStream` per project; a change sends `EngineMessage.recompile` (a batch member with no edit, so it coalesces with edits). `setPackagesDir` returns before the recompile; tests poll for the result.
- **Completion scan.** Local packages are scanned per completion request (`<dir>/<ns>/<name>/<version>/typst.toml`, names from the folders, description and `compiler` from `[package]`, via the `toml` crate already in the lock file as a direct dependency) and appended to the preview index list; typst-ide sorts and dedups. A manifest that fails to parse is skipped (typst could not compile it either). Shortcut: rescanned each request, no cache; fine for tens of packages.
- **Bookmark.** `LocalPackagesFolder` stores one app-scope bookmark in `UserDefaults` (`TypstCore.localPackagesBookmark`), reuses `ScopedAccess` (resolve, start, stop in `deinit`), refreshes a stale bookmark in `restore()`, and drops one that no longer resolves. On switch the runtime dir changes first and the old access ends after.
- **Settings.** The panel is pre-pointed at the real home's `Library/Application Support/typst/packages` through `getpwuid` (the sandbox `NSHomeDirectory` is the container).
- **Entitlements.** `files.user-selected.read-write` (a superset of read) and `files.bookmarks.app-scope` are already present; nothing else is needed. Rust reads the folder with POSIX calls under the process-wide grant, as for project roots.

### Unit: file management in the sidebar (DESIGN 13)
- **Where it lives.** Core: `FileOperations.swift` (an extension of `Project`), `EngineMessage.relocate` and `.drop`, `Buffer.rekey(to:)`, `EditLog.relocate`, `RelPath` helpers. Bridge: two functions, `tb_world_relocate_overlay(old, new)` and `tb_world_remove_overlay(path)`. App: `FilesController` (targets, alerts, watcher), `FileWatcher` (FSEvents), the Files tab rewrite, File menu items.
- **`.relocate` carries a prefix, not a list of pairs.** `.relocate(from:to:overlays:seq)`: the engine derives each overlay's new path and the new main with `RelPath.replacing`. The main may be at or under the moved path without being among the overlays handed over, and a diverged overlay's mark moves with it (otherwise the engine would never compile again). The message and `.drop` carry a `Seq` that the engine folds into `appliedSeq`, so `exportPDF` and the stale-diagnostic cutoff see the file operation as covered by the next compile.
- **File store reset.** `tb_world_compile` already resets the file store at the start of every compile, and a relocate always makes the batch dirty, so no separate reset call exists.
- **Quiesce is a loop.** Step 0 and 1 repeat until, in one synchronous check, no writer is running, no buffer at or under the path is dirty and no `open(_:)` of such a path is in flight (each await lets a keystroke, Cmd-S or a sidebar click in). `save(under:)` saves only those buffers. `saveAll` captures each path when it queues the work. Autosave is paused with a counter, and file operations are serialized (`beginFileOp`/`endFileOp`).
- **Trash order.** The Trash call comes before dropping overlays and closing buffers (the spec lists it after). Nothing suspends in between, so success looks the same, and a failing Trash now leaves every buffer open instead of closed.
- **No document left.** `main` is not optional. If the main was trashed and no `.typ` is left in the root, `main` keeps the trashed path: the compile reports the missing file and the preview is empty.
- **Stale diagnostics and outline.** `staleRoots`/`staleSince`: results of compiles before the operation are filtered by path prefix. Diagnostics use the latest result, the outline uses the last successful compile, so a failing compile after a rename keeps the outline's old entries hidden. Search: `fileRevision` bumps and in-flight searches answer nil; the app clears its results and the search tab reruns.
- **New items.** Created on disk at once under "Untitled.typ" / "untitled folder" (numbered when taken), then the row goes into inline rename; Esc keeps the placeholder name, as in Finder. Rename commits on Return and when focus leaves the field.
- **Not done.** Double-click-pause on a selected row does not start editing (Return, the context menu and File > Rename do). Moving into a folder that holds the name asks like Finder (Keep Both, Stop, Replace; design/14d). Rows are dragged as their file URL and the list has one URL drop destination: `Project.dropItems` moves a URL inside the project root and copies any other, so a project file dragged in from a Finder window moves too (deviation from "Finder drops copy"; one payload type avoids stacked drop destinations).
- **Watcher filter.** Atomic writes create and rename temporary files next to the file, so file-level events alone would rescan on every autosave. `FilesController.isStructural` ignores hidden names, sandbox temporaries (`.sb-`) and created or renamed paths that are already in the tree and exist; the scan equality check below stays as the backstop.
- **Trashed main on reopen.** `Project.init` opens and selects the main only if it exists, and `PreviewModel.clear()` empties the preview when the trash leaves no document (a failed compile still keeps the last good pages). Replies for a path that moved while a click or hover was in flight are dropped.
- **Echo of own operations.** Not tracked by a flag: each operation rescans the tree synchronously, and `refreshFiles` changes nothing (not even `fileRevision`) when the scan equals the current tree, so the watcher's echo is a no-op. The watcher is deferred while a name is being edited. `refreshFiles` also sends `.recompile`.
- **Cmd-Delete.** The File menu item is enabled only while `fileListFocused` (a `focusedValue` set on the list, not a scene value) is true and nothing is being renamed; a disabled item does not take the key, so the editor keeps "delete to line start".
- **Unverified.** The UI was not launched: the focus-dependent enabling of Move to Trash, the Return key on a selected row, inline rename selection, drag and drop (internal and from Finder), the DisclosureGroup selection of folder rows and FSEvents delivery under the sandbox were compiled only.

### Unit: welcome window, new project, templates (DESIGN 14)
- **Separate `Window` scene, not the nil branch of the project `WindowGroup`.** A group shares `defaultSize`/resizability across its windows, so a fixed 440 pt welcome window and 1280 pt project windows cannot both hold. Restored nil-valued windows from older builds showed the welcome view inside a 1280 × 820 titled window; they now redirect. Routing external events to the welcome scene keeps the group from ever creating a nil window, so the redirect has no race with `onOpenURL`.
- **Window height.** `.windowStyle(.hiddenTitleBar)` still adds the 32 pt title-bar inset to the content height, so the view's frame is 528 pt with `.ignoresSafeArea()` for a 560 pt window (measured with the window list).
- **Template list in Rust, not a second Swift decode.** The index is already parsed in Rust; doing the template filter there keeps one compiler-compatibility rule. The JSON is built once per applied index.
- **Fetch through typst-kit, not a Swift tar/gzip reader.** It reuses the verified downloader and cache, works on iOS, and the template's own `@preview` import is cached afterwards. A one-off network probe (`charged-ieee` 0.1.4) produced `main.typ` and `refs.bib` with `#import "@preview/charged-ieee:0.1.4": ieee`; the committed tests stay offline.
- **Never merge into an existing folder.** NSSavePanel offers "Replace"; both creation paths refuse an existing destination (`createDirectory(withIntermediateDirectories: false)`, and an explicit check that also sees dangling symlinks), so a user's folder is never changed.

### Unit: thesis features in parallel lanes (DESIGN 15)
- **How it was built.** Five workers in isolated clones of a scratch git repo (never the project folder), one lane in the real checkout for the warm Rust target, merged with real 3-way merges. Shared files got one-line hooks; each lane owned new files and its own `Commands` struct. Lanes never launched the app (one bundle id, shared defaults and container); only the coordinator did.
- **Missing File-menu items.** `CommandGroup(after: .saveItem)` content is never shown here, which had also hidden Save (⌘S still worked) and Export PDF… since the welcome `Window` became the first scene. Save, Export and Snapshots now sit `after: .newItem`.
- **Blank editor after the comfort lane.** The text view laid out (ruler numbers, `_NSTextViewportElementView`s with frames, correct storage attributes) but drew no text. Cause, found by bisecting app files in a separately identified build (`PRODUCT_BUNDLE_IDENTIFIER=…debug`, so the user's instance stayed untouched): `LineNumberRuler` overrode `draw(_:)` (to paint a theme background), even though it called `super.draw` for the default theme. The ruler's drawing reaches over the text (its rect and layer extend beyond `ruleThickness`), so an opaque fill there (`super.draw` in the override, or a theme fill over the whole rect) covered every line; hiding the ruler in lldb brought the text back. The ruler no longer overrides `draw(_:)`, and a theme fills only `0..<ruleThickness` at the start of `drawHashMarksAndLabels(in:)`. Checked in the window for Default and Dracula, plus fold all/unfold all, split editor on/off, Focus Mode and text size.
- **Split editor off left a gap.** A hidden trailing pane kept its width in `NSSplitView`; `Split.layout()` now gives it back to the leading pane (also fixes the blank strip seen on the first merged launch). The lane's offscreen tests could not see this because they never render.
- **Click/selection lag report.** Profiles and an Animation Hitches trace during the user's clicks showed no hitches, no hangs and an idle main thread: the lag was not a performance problem. Cause: the caret is a `DecorationView` layer (the system one is hidden when "Animated caret" is on), refreshed from `textViewDidChangeSelection`. NSTextView sets a click's or drag's selection with `stillSelecting: true` while the button is down and sends that delegate call only on mouse-up, so the drawn caret, selection and current line trailed every press by its length. `EditorTextView.setSelectedRanges(_:affinity:stillSelecting:)` now refreshes the decorations on each tracking change; the delegate's heavier work (tables, word count, cursor sync) still runs once on mouse-up. Checked with lldb on the Debug build: every `stillSelecting` change during a drag is followed by a refresh.
